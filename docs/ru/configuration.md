# Конфигурация

[English](../en/configuration.md) | **Русский**

TExec читает JSON/YAML и переменные `TEXEC_*`; переменные окружения имеют приоритет.
Создайте конфигурацию командой `texec setup`, затем выполните
`texec server --config /path/to/config.json`. Флаг `--no-config` позволяет использовать
только переменные окружения.

| Параметр | Назначение |
| --- | --- |
| `TEXEC_DB_DIALECT` | `sqlite`, `postgres` или `mysql` |
| `TEXEC_DB_HOST` | Файл SQLite или адрес сервера БД |
| `TEXEC_PORT` | HTTP-порт, по умолчанию 3000 |
| `TEXEC_WEB_ROOT` | Публичный URL с префиксом пути, если он есть |
| `TEXEC_TMP_PATH` | Рабочий каталог, по умолчанию `/tmp/texec` |
| `TEXEC_ACCESS_KEY_ENCRYPTION` | Ключ шифрования секретов в base64 |
| `TEXEC_METRICS_ENABLED` | Метрики Prometheus |

Полный [справочник параметров EN](../en/reference/configuration.md),
[справочник CLI EN](../en/reference/cli.md), [схема](../../config.schema.yaml).
Ключ шифрования сохраняйте вместе с резервной копией: его замена делает старые секреты
недоступными. За обратным прокси укажите публичный URL. Доступны локальные учётные записи,
LDAP и OpenID Connect; параметры провайдеров перечислены в справочнике.

## Оформление

Администратор выбирает глобальную палитру в **Управление → Общие настройки → Оформление**.
**По умолчанию** в этом разделе — исходное оформление TExec. Глобальный выбор применяется
на странице входа и в аккаунтах без персонального переопределения.

Пункт **Аккаунт → Оформление** расположен сразу под **Редактировать аккаунт**.
**По умолчанию** здесь наследует глобальное оформление. Другая палитра сохраняется в базе
как персональная настройка аккаунта и используется в разных браузерах. Выбор карточки меняет
предпросмотр, **Сохранить** применяет оформление. Прежняя кнопка солнца и луны независимо
переключает светлый и тёмный режим в текущем браузере. Другие открытые сессии получают
глобальную палитру после обновления страницы или возврата фокуса в окно браузера.

Доступны десять палитр: TExec, Ocean, Indigo, Nord, Dracula, Solarized, Gruvbox, Catppuccin,
Rosé Pine и Graphite. У каждой есть адаптированные к приложению светлая и тёмная версии.
Дополнительно доступны «Высокий контраст», «Янтарный контраст» и «Синий и оранжевый».
В них усилены границы полей и клавиатурный фокус, сохранены подписи и значки статусов.
В сине-оранжевой теме успех и ошибка различаются без опоры на красно-зелёную пару.

Тесты палитр проверяют текст и смысловые цвета на фоне страницы, карточек и тонированных
поверхностей: не менее 4,5:1 для обычных тем и 7:1 для контрастных. Это проверка цветов
палитры, а не заявление о полном соответствии приложения WCAG.
См. [рекомендации WCAG по контрасту](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

Глобальный идентификатор хранится как `server.appearance.theme` и изменяется через
`PUT /api/settings` (поле `appearance_theme` вместе с `use_remote_runner`). Персональный —
через `POST /api/user/options`, например `{"key":"appearance.theme","value":"\"nord\""}`.
Значение `"value":"\"\""` возвращает наследование. Принимаются только идентификаторы
встроенных тем; CSS, скрипты и внешние темы не загружаются. Миграция схемы базы не требуется.

## Общие настройки сервера

Администратор может открыть **Управление (шестерёнка) → Общие настройки** и включить
**Использовать удалённых исполнителей по умолчанию**. Настройка действует для всех
проектов, хранится в базе и сохраняется при пересоздании контейнера. По умолчанию
она выключена: задачи без тега выполняются на сервере. При включении такие задачи
используют активных удалённых исполнителей, отмеченных как используемые по умолчанию;
подходящие исполнители проекта имеют приоритет над общими. Явный тег в шаблоне
или инвентаре всегда выбирает удалённого исполнителя независимо от этой настройки.

Сохранение применяется к новым задачам без перезапуска сервера. Задачи, уже находящиеся
в очереди работающего сервера, сохраняют способ выполнения, а назначенные задачи
остаются на своих исполнителях. Если после перезапуска сервер восстанавливает из БД
задачу без назначенного исполнителя, используется текущее значение настройки.
Если подходящие исполнители не в сети или заняты, задача ждёт. Если ни один включённый
исполнитель не соответствует условиям выбора, запуск завершается ошибкой.
Автоматического перехода к выполнению на сервере нет.

Удалённое выполнение настраивается через интерфейс. Настройка входит в полную резервную
копию БД, но не в экспорт проекта в JSON. Для автоматизации доступны административные
методы `GET /api/settings` и `PUT /api/settings` с телом
`{"use_remote_runner": true}` или `{"use_remote_runner": false}`.

Поле **Часовой пояс расписания** действует на расписания всех проектов. Пустое
значение использует часовой пояс сервера (при запуске в Docker — контейнера).
Приоритет: `TEXEC_SCHEDULE_TIMEZONE` → `schedule.timezone` в JSON/YAML → значение
из базы → часовой пояс системы. Если задана переменная окружения или конфигурация,
поле заблокировано: интерфейс показывает используемое значение и причину блокировки.
Значение в базе сохраняется и снова применяется после удаления внешнего параметра.
Изменение внешней конфигурации требует перезапуска сервера. Сохранение значения в
базе сразу пересчитывает периодические расписания на текущем сервере; остальные
работающие серверы обнаруживают изменение в течение пяти секунд. Однократные
запуски сохраняют абсолютное время выполнения. Очистите поле для возврата к
системному часовому поясу. В `PUT /api/settings` можно передать строку
`schedule_timezone` вместе с `use_remote_runner`; отсутствие поля сохраняет прежнее значение.

## Шаблоны сообщений проекта

В **Панель управления → Настройки → Оповещения → Telegram → Шаблоны сообщений** можно
задать отдельный текст для успешной и завершившейся ошибкой задачи. У каждого канала
свои шаблоны. Внутри Telegram вкладка **Основные** содержит настройки чата и бота,
а **Шаблоны сообщений** — редактор. Редактирование доступно после включения канала. Отключение сообщений об успехе
или ошибке в конкретном шаблоне задачи сохраняет приоритет. Оповещения узлов
рабочего процесса и запросы подтверждения настраиваются отдельно.

Доступны переменные `project.name`, `template.name`, `task.id`, `task.status`,
`task.started_by`, `task.url`, `task.message`, `task.version`, `task.error`,
`date`, `time` и `timezone`. Для вставки используйте `{{ task.id }}` или список
переменных. Это обычный текст без HTML и исполняемых выражений. Сохранённый текст
и язык значения `task.status` не меняются при смене языка интерфейса. Отдельного
выбора языка сообщений нет. `date` и `time` — момент завершения
задачи в выбранном часовом поясе. Отсутствующее значение отображается как `—`.
`task.started_by` — имя пользователя или проектного API-токена, если задача
запущена им; при отсутствии автора — `—`.

`task.error` содержит краткую выдержку из строк журнала с признаками ошибки,
а не весь журнал. Известные форматы паролей и токенов маскируются, но произвольный
секрет в тексте ошибки распознать невозможно. Максимум — 3000 символов на шаблон
и 4000 символов в готовом сообщении; длинный результат обрезается.

Предпросмотр использует примерные данные. **Тестировать оповещение** отправляет
выбранный пример с пометкой теста, используя текущие значения чата, бота и шаблона
в форме, без сохранения. У двух вкладок общие кнопки тестирования и сохранения. Канал должен быть включён и настроен. **Сбросить этот шаблон**
восстанавливает только выбранный шаблон — успех или ошибку — на текущем языке
интерфейса аккаунта. Поддерживаются все 15 языков; второй шаблон не меняется.
Кнопка **Сохранить** применяет тексты вместе с настройками канала. До первого сохранения действует прежний формат сообщений.
Настройки входят в резервную копию проекта и применяются на сервере, в том числе
к задачам удалённых исполнителей.

## Оповещения в Telegram

Откройте **Управление (шестерёнка) → Оповещения → Telegram** и сохраните общий
токен бота, полученный у BotFather. Общие настройки доступны администраторам.

В **Проект → Панель управления → Настройки** откройте вкладку **Оповещения → Telegram**.
Включите Telegram, укажите ID чата и сохраните. По умолчанию канал выключен
для каждого проекта. У бота должно быть право отправлять сообщения в этот чат.
Настройки подавления оповещений об успехах и ошибках в шаблонах продолжают действовать.

По умолчанию выбрано **Использовать глобальный токен бота**. Снимите галочку,
чтобы задать отдельного бота для проекта. Повторное включение галочки удаляет
переопределение. Сохранённые токены не отображаются и не возвращаются через API.
Пустое поле замены сохраняет текущий токен; для удаления общего токена есть кнопка
**Удалить токен**. Настройки оповещений проекта доступны пользователям с правом
изменения проекта.

**Тестировать оповещение** отправляет сообщение с текущими значениями формы, не сохраняя
их. В общих настройках укажите отдельный ID чата для теста — он не сохраняется.
В настройках проекта используются выбранный общий или собственный бот и указанный в форме
чат. Результат появляется под полями. Тест не запускает задачу.

Настройки каналов хранятся в базе отдельно, с включением и адресом назначения
для каждого проекта. Токены используют серверную конфигурацию шифрования секретов;
сохраняйте ключ вместе с резервной копией БД. `vault check`, `vault rekey` и резервные
копии секретов при ротации учитывают токены оповещений. Перезапуск после изменения
настроек не нужен. Экспорт проекта в JSON включает шаблоны сообщений каналов, но не токены,
адреса чатов и состояние включения. После импорта каналы выключены.

## Резервное копирование

Сохраняйте конфигурацию, ключи шифрования и базу вместе. Перед копированием файла SQLite
остановите экземпляр либо используйте согласованный backup SQLite. Для PostgreSQL/MySQL
применяйте штатные средства БД. Экспорт проекта в JSON не заменяет полную копию экземпляра.

## Исполнители и права доступа

- **Проект → Исполнители** — управление исполнителями этого проекта. Создание,
  изменение, удаление, очистка кэша и перевыпуск токена регистрации требуют права
  **Управлять ресурсами проекта**. Участники могут просматривать список;
  токены исполнителей в него не входят. Для удалённого выполнения включите
  **Использовать удалённых исполнителей по умолчанию** в **Общих настройках**
  или укажите тег исполнителя в шаблоне/инвентаре.
  Подходящие исполнители проекта имеют приоритет над общими; задачи без тега
  используют исполнителей, отмеченных как используемые по умолчанию.
- **Управление → Роли** — глобальные роли, доступные администратору.
  **Проект → Команда → Роли** — роли конкретного проекта. Для изменения требуется
  право **Управлять пользователями проекта**. Назначение роли — на странице команды.
- **Шаблон → Разрешения** — дополнительные права пользовательской глобальной или
  проектной роли на отдельный шаблон. Для изменения требуется право
  **Управлять пользователями проекта**. Эти разрешения дополняют права роли,
  а не отнимают их.
- Идентификатор роли уникален в пределах экземпляра и не меняется после создания.
  Идентификаторы встроенных ролей зарезервированы. Перед удалением роли нужно
  снять её назначения пользователям и удалить её разрешения на шаблоны.

## Сводки Ansible

Задачи Ansible сохраняют статистику хостов, ошибки и этапы выполнения
в основной базе данных. Откройте завершённую задачу и вкладку **Сводка**.
Это работает при локальном выполнении и через удалённых исполнителей.
Счётчики берутся из `PLAY RECAP`; проигнорированные и обработанные через rescue
ошибки остаются в списке, даже если итоговый статус хоста успешный.

Поддерживается стандартный текстовый вывод Ansible, включая цветной вывод
и многострочные ошибки в формате JSON/YAML. Скрытие данных через `no_log`
сохраняется. Пользовательские stdout callback могут иметь несовместимый формат.
Если задача закончилась до recap, интерфейс объясняет отсутствие статистики. Текст ошибки в сводке
ограничен 1000 символами; полный вывод остаётся в журнале задачи.

При удалении задачи удаляется её сводка. Резервная копия базы содержит сводки и журналы задач;
экспорт проекта в JSON не содержит историю выполнения.

## Ограничения развёртывания

Используйте один сервер TExec с локальным выполнением, удалёнными исполнителями или Docker.
Для входа доступны локальные учётные записи, LDAP, OpenID Connect и TOTP. Аудит хранится в БД.
